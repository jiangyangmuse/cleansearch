## 8 追加轮次 2026-11-14 18:24（CI 失败与修复）

**CI 首轮失败**：run [43579930415](https://github.com/jiangyangmuse/cleansearch/actions/runs/43579930415) 在 `API tests` 步失败（本机 489 全绿）。

**复现**：GitHub API 取日志需 token（403），改用 `docker run --rm -v 'D:/agent/llq:/w' -w /w python:3.12-slim` + `pip install -e 'apps/api[dev]'` + `pytest apps/api -q -o addopts=`，拿到与 CI 相同的 2 个失败：

- `test_health_reports_api_version_and_capabilities`：`capabilities['filters'] is False`
- `test_health_capabilities_follow_registered_routes`：`AttributeError: '_IncludedRouter' object has no attribute 'path'`

**根因**：CI 装的是全新依赖（fastapi 0.162.7 / starlette 1.10.0），`app.routes` 里 `include_router` 被收成 `_IncludedRouter` 占位对象，既没有 `.path` 也没有 `.methods`；本机是旧版本，路由表是展开的，所以只有 CI 会挂。原实现 `{(method, route.path) for route in app.routes}` 因此把 `filters`/`bookmark_status`/`model_test` 全判成缺失。

**修复（`037f3d6`）**：`_capabilities()` 改成两条来源——`app.openapi()['paths']`（覆盖 `include_router` 注册的接口）+ 路由作用域匹配（覆盖 `include_in_schema=False` 的 `vitals`、`opensearch`），并排除 SPA 兜底 `/{full_path:path}` 造成的伪命中；测试不再读路由对象结构，改为改 `CAPABILITY_ROUTES` 后断言结果。
