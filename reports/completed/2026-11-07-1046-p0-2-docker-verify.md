## 1 任务

**目标**

用 Docker Desktop 跑通 docker compose：同源部署、固定样本冒烟、真实 SearXNG 搜索、容器重建后书签与 token 持久化。

**验收标准**

- docker compose up -d --build 后 API 与 SearXNG 都起来，端口只绑回环。
- 固定样本冒烟 16/16；同源页面可访问。
- docker compose down + up 后书签和 token 仍在。
- 切 SEARCH_PROVIDER=searxng 后容器内真实搜索可用，指定引擎验收通过。
- 拿不到的证据写明原因。

**不做**

- 容器内接千问总结（需 host.docker.internal 与模型同时可用）。
- 把 Docker CLI 永久加进系统 PATH（只在本轮命令里拼路径）。

## 2 做了什么

1. 确认 Docker Desktop 已安装并在运行：CLI 在 C:\\Users\\HUAWEI\\AppData\\Local\\Programs\\DockerDesktop\\resources\\bin（用户级安装，未进当前 shell 的 PATH）；Engine 29.9.2 linux，Compose v5.6.1。
2. 停掉占用 8888/8000 的宿主机原生 SearXNG 与 fixture 服务，执行 docker compose up -d --build：llq-api 镜像 242MB 构建成功，searxng/searxng:latest 387MB，两个容器只绑 127.0.0.1。
3. 固定样本阶段（.env 里 SEARCH_PROVIDER=fixture）：/api/health 显示 provider=fixture、web_dist=/web；smoke.ps1 16/16。
4. 持久化：写一条书签（201）→ 记录 token 前缀 → docker compose down → up（卷 llq_bookmarks 保留）→ 书签仍在、token 前缀一致。
5. 真实上游阶段：.env 改 SEARCH_PROVIDER=searxng，docker compose up -d --force-recreate api；/api/health 显示上游 http://searxng:8080。
6. 把 bing/yahoo/sogou 的启用写进仓库 searxng/settings.yml 并 docker compose restart searxng，保证 compose up 后引擎集与宿主机原生一致。
7. 验收：3 条默认查询各 10 条结果；verify-searxng.py --engines y gc 9/9；浏览器打开容器页面 10 张卡片、无 JS 错误。
8. 清理测试书签；文档同步（README / 决策 M10-D1…D4 / 进展与欠账 P0-2 置完成）。

## 5 关键决策

| 决策 | 备选 | 理由 |
| --- | --- | --- |
| 分两阶段验收（fixture 冒烟 / searxng 搜索） | 一套配置跑全部 | 冒烟里多条断言依赖固定样本，真实上游必然失败，混在一起没有意义 |
| 引擎启用写进仓库 settings | 只在本机容器里改 | 别人 compose up 也要拿到同一引擎集 |
| 容器验收不接千问 | 配 host.docker.internal 一起测 | 本轮目标是部署与持久化；模型链路已在宿主机验过，混进来会掩盖问题 |
| 测试数据用后删除 | 留着当样本 | 书签是用户数据区，验收证据截图已足够 |

## 6 遗留与风险

- 容器内与宿主机原生的引擎可用性不同（容器里 ddg 可用、google cse 偶发超时；宿主机相反），跨环境结论不能互推。
- docker CLI 未进当前 shell PATH，脚本里需显式拼路径；换用户/机器要改。
- 容器内模型（千问）未接；COMPOSE_LLM_BASE_URL 只是预留。
- Windows 下 docker compose down 后卷仍在，但若执行 down -v 会连数据一起删，需在文档里持续强调。
- 本轮把宿主机原生 SearXNG 停了，现在 8888 由容器提供；原生实例的启动命令仍在 README。
