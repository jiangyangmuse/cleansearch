## 2 做了什么

1. **筛选与历史**。一次历史导航同时切换查询和筛选时，取消旧查询的 AI 检索。验证有效筛选在响应中逐字段回显，错配时保留地址栏条件、提示未生效，并提供清除筛选后继续搜索的入口。站点规范化在反复读取链接时保持同一域名。
2. **浮层**。锚定布局为上下间距留出空间，矮视口贴底，缺少原生 popover 时浮层在视口内定位，关闭清除未提交的草稿。768×561 复现底部到 y=567，修正后底部到 y=555。1280×280 实测内部滚动 83px。
3. **能力探测**。加载期间先禁用依赖能力的控件和请求。入口读取一次 health 并共享给搜索页，超时上限 5 秒。版本过低时禁用依赖当前契约的功能，达标后按能力逐项处理。服务端以 HTTP 方法和路径推导能力，筛选另核对响应字段。
4. **抽屉与 LAN**。复核 1024px 单列、1180/1181 两侧和 1440px 三栏。原 README 命令仍绑定回环，补 `-BindAddress` 并从 Wi-Fi 网卡 IP 实测。Host 校验覆盖大小写、带端口、IPv6、越界端口、路径、凭据和重复 Host。

## 5 关键决策

- 本轮采用隔离构建、测试端口、临时数据库和本地模型桩。日常 8000 保留本轮开始前的实例及数据。

- 继续采用原生自动 popover；仅在平台缺少相应能力时用固定定位回退。

## 6 遗留与风险

- 本机通过 Wi-Fi IP 自访覆盖启动和 HTTP 行为，另一台手机能否到达仍要看 Wi-Fi 和 Windows 防火墙。真机访问需从同一 Wi-Fi 打开 health 再测试搜索和收藏。
- 本轮真实上游成功覆盖筛选矩阵。上一轮 Google 后缀的连通性需在索引所列的部署场景补验。
- 日常 8000 尚未加载本次复核修复。部署时保留原 provider、数据路径和模型选项，再按 README 换版步骤核对。
