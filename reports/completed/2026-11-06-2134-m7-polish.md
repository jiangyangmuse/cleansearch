## 1 任务

**目标**

完成构建方案 M7 打磨：搜索/总结缓存、键盘快捷键、暗色主题、移动端抽屉、错误态收敛。

**验收标准**

- 重复查询命中缓存，`meta.cached=true`，且命中后仍能生成总结。
- 单页总结同内容复用，响应 `cached=true`。
- `/`、`j`/`k`、`Enter`、`b`、`s`、`Esc` 可用且不与输入框冲突。
- 主题三态可切换并持久化；窄屏侧栏变抽屉。
- 断网 / LLM 超时 / 引擎全挂仍落到统一错误态。测试、冒烟、浏览器断言通过。

**不做**

- 向量排序、LLM 复核重排、PWA 离线缓存、浏览器扩展、桌面壳。

## 2 做了什么

1. 新增 `app/db/cache.py`：`search_cache`（qkey + TTL）与 `summaries`（content_hash）两张表，与书签同库；提供 `search_key()` 与 TTL 过期清理。
2. `POST /api/search` 接入缓存：命中直接返回已分档结果，标记 `cached=true`，并按新 `sid` 重新登记会话快照。
3. `POST /api/page/summarize` 按 `content_hash` 复用总结；仍抓一次页面保证正文没变，响应加 `cached`。
4. 配置新增 `CACHE_ENABLED`、`CACHE_TTL`；测试默认关闭缓存，缓存专项用例自行开启。
5. 前端主题：`src/theme.ts` + `ThemeToggle`，三态循环写入 `localStorage`，CSS 从媒体查询改为 `[data-theme="dark"]`。
6. 快捷键：`App` 内统一监听，选中项用 ref 保存（连按 `j` 不丢步）；`s` 通过自定义事件驱动侧栏；`g s` 回搜索页。
7. 窄屏：`<1080px` 侧栏变底部抽屉（62vh）+ 右下角「AI 总结」开关；桌面保持 sticky。
8. 结果卡与元信息：`card--selected` 高亮、缓存徽标、快捷键提示条。

## 5 关键决策

| 决策 | 备选 | 理由 |
| --- | --- | --- |
| 缓存存最终分档结果 | 存原始候选再重算 | 命中要真的省掉过滤/打分；代价是调参后需清缓存 |
| 命中后重新登记 sid | 复用缓存里的 sid | 快照在内存、缓存落盘，生命周期不一致 |
| 单页总结仍抓页面校验 hash | 只按 URL 缓存 | 否则改版后会返回旧结论 |
| 测试默认关缓存 | 全开 | 同 hash 不同桩输出会让用例互相污染（实际踩到过） |
| 选中项用 ref | 只靠 state | 连按 j 时闭包读到旧值，移动会卡在第一条 |
| 主题值由 JS 写入 data-theme | 纯 CSS 媒体查询 | 要支持手动覆盖自动值 |

## 6 遗留与风险

- 缓存不主动失效：改了打分/安全规则后需清 `search_cache` 表或等 TTL。
- 缓存表没有容量上限，按 TTL 清理；长期运行需要定期 `purge`。
- 快捷键只在桌面浏览器验证，移动端软键盘场景未覆盖。
- 抽屉只做了「展开/收起」，没有构建方案里的拖拽上拉。
- 深色模式下个别 hover 态对比度未逐项打磨（结果卡/书签卡已看过）。
