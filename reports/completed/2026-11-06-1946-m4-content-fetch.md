## 1 任务

**目标**

实现首版实施计划 M4：统一受控抓取入口，开启搜索正文增强、单页总结与死链检测。

**验收标准**

- 抓取拒绝非公网地址（回环、私网、链路本地、元数据地址），包括重定向目标。
- 限制响应大小（2MB）与耗时（2.5s），超出截断并标记。
- 正文不可用时保留摘要版，并在 `meta.failed`/`degraded` 与 `done.partial` 上明示。
- 单页总结返回固定结构；死链检测可批量标记书签。
- 后端测试全绿、冒烟通过、浏览器断言通过。

**不做**

- 三源实时黑名单 feed 与 `/go` 中转（需 API key）、Playwright 渲染兜底、r.jina.ai 兜底、总结结果落库缓存。

## 2 做了什么

1. 新增 `app/core/fetch.py`：`SafeFetcher` 手动跟随重定向，逐跳复检；DNS 结果全部必须是公网地址；协议/主机名/IP 字面量三重拦截；超时、大小、内容类型限制。
2. 新增 `app/core/extract.py`：`Article` 提取器，trafilatura 可选优先，标准库 `HTMLParser` 回退；丢弃 script/nav/footer 与面包屑，按块切段，计算字数、阅读时长、content_hash。
3. `app/core/summarize.py` 增加 `enrich_with_full_text()`：并发抓前 5 条正文，单条失败保留摘要；桩在单来源时改为摘句。
4. `GET /api/summarize` 支持 `mode=full`，`meta` 增加抓取统计，`done.partial` 反映降级。
5. 新增 `POST /api/page/summarize`（单页总结，四段结构）与 `app/routers/page.py`。
6. 新增 `POST /api/bookmarks/check`（并发 5、64KB 试探、批量写 `dead`）。
7. 前端：侧栏「增强（抓正文）」按钮与抓取/降级脚注；`/s?u=` 单页总结页；启动台「检测死链」与「失效」标记。
8. 新增 `app/deps.py` 统一提供 `get_fetcher`，测试用 `dependency_overrides` 注入 MockTransport。
9. 冒烟增加「内网地址拦截」；`.env.example` 增加抓取参数。

## 5 关键决策

| 决策 | 备选 | 理由 |
| --- | --- | --- |
| 解析后校验全部 IP 才发请求 | 只校验 URL 字面量 | 多 A 记录与 DNS 重绑定会把内网藏进解析结果 |
| 不做 IP 钉扎 | 自定义 transport 绑定解析到的 IP | 钉扎要手工处理 SNI/Host，复杂度高，M4 先记录为已知窗口 |
| 重定向手动跟随 | 交给 httpx follow_redirects | 自动跟随会绕过每一跳的目标校验 |
| 提取器双轨 | 只装 trafilatura | 本机/离线环境装不上时不能整条链路失效；响应里标明实际提取器 |
| full 模式失败保留摘要 | 失败即整条流报错 | 实施计划要求「正文不可用时保留摘要版并标明素材来源」 |
| 死链检测复用 SafeFetcher | 直接 httpx 并发探测 | 书签是用户可控输入，必须走同一套 SSRF 护栏 |
| 新增 `FETCH_EXTRA_CIDRS` | 放宽 is_private 判断 | 本机代理把域名解析到 198.18/15；显式白名单比破坏默认严格性安全 |

## 6 遗留与风险

- DNS 重绑定窗口未封：解析与连接之间地址可能变化（M4-D2）。
- 不执行 JS：SPA 页面提取不到正文，会返回 422；Playwright 兜底留给后续。
- 没有正文与总结缓存：同一 URL 重复抓取，重复调用模型；`summaries` 表尚未启用。
- 死链判定只看状态码，403/429 会被误判为失效。
- 单页总结的 `key_data` 恒为空数组，「原文锚点」未实现。
- 本机网络经透明代理，真实公网访问需要 `FETCH_EXTRA_CIDRS`，与生产默认配置不同。
