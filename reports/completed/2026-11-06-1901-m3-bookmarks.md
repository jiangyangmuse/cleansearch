## 1 任务

**目标**

实现首版实施计划 M3：结果卡一键收藏、书签分组与搜索、浏览器 Netscape HTML 导入导出。

**验收标准**

- 结果卡能一键收藏，重复收藏不产生重复行。
- `/bookmarks` 页面可分组浏览、搜索、添加、删除、新建分组。
- 导入再导出后 URL / 标题 / 分组保持一致。
- 重复导入有明确规则且可测。
- `python -m pytest apps/api` 全绿、冒烟通过、浏览器断言通过。

**不做**

- 死链检测（M4）、标签 UI、拖拽排序、数字键快捷启动、Chrome 扩展与 bookmarklet（M8）。

## 2 做了什么

1. 新增 `app/db/schema.sql` 与 `app/db/repo.py`：SQLite WAL；`bookmarks.url_key`（canonical URL）唯一去重；FTS5 虚表 + 三个触发器，FTS5 建不起来时自动降级 LIKE。
2. 新增 `app/core/netscape.py`：`HTMLParser` 解析 `<DL>/<H3>/<A>` 层级，导出时按分组生成 Netscape 结构。
3. 新增 `app/routers/bookmarks.py`：列表/新建/更新/删除、分组创建、multipart 导入、HTML 导出。
4. 收藏语义：手动重复→补空标题/备注并可改分组（`deduplicated=true`）；导入重复→纯跳过，不覆盖用户整理结果；分组按需创建，不给全重复文件留空分组。
5. 前端新增 `BookmarkPage`（`/bookmarks`）：分组 chip、搜索、网格卡片、添加表单、新建分组、删除、导入文件、导出下载；`main.tsx` 按 pathname 分派页面。
6. 结果卡加「收藏」按钮，四态文案（收藏 / 收藏中 / 已收藏 / 已在书签）。
7. `/api/health` 增加 `bookmarks` 计数；`smoke.ps1` 增加两项只读书签检查。
8. 测试 12 例：CRUD、去重规则、搜索/分组过滤、500 条导入、往返一致、重新导入只跳过、导入不动已有分组、API 层校验。

## 5 关键决策

| 决策 | 备选 | 理由 |
| --- | --- | --- |
| `url_key` = canonical URL 唯一列 | 直接拿原始 url 去重 | 一键收藏常带 `utm_*`，原样存会出现多条同页 |
| 导入重复纯跳过 | 导入时覆盖标题/分组 | 用户手动整理的分组不该被浏览器导出文件冲掉 |
| 分组按需创建 | 导入前先建好全部目录 | 全重复的导入会留下空分组，用户还得手动清理 |
| FTS5 失败自动降级 LIKE | 直接报错要求编译 FTS5 | 不同平台 SQLite 编译选项不同，能搜比搜得快更重要 |
| 导入用 multipart | 直接收 raw HTML body | 与设计文档 §6.4 一致，也方便浏览器/curl 直接传文件 |
| 前端按 pathname 分派 | 引入 react-router | 只有两个页面，路由库的收益抵不上依赖与心智成本 |

## 6 遗留与风险

- 单进程 SQLite，多 worker 写会锁冲突；部署多进程需换 Postgres 或串行化写。
- 标签表已建但无 UI，`tags` 只在 API 写入时落库，列表不返回。
- 没有死链检测与 favicon 缓存；图标直连目标站，离线时会显示裂图。
- 导入同步解析，2 万条级别会阻塞请求；建议后续改后台任务 + 进度。
- 浏览器测试用独立临时 DB，未覆盖「真实 `data/cs.db` 已有大量数据」的性能表现。
