## 1 任务

**目标**

兑现构建方案 D7「书签一键添加三通道」：bookmarklet、Chrome/Edge 扩展、PWA share_target，并用本地 token 收口跨域写入。

**验收标准**

- `/tools` 能生成可拖拽的 bookmarklet，带 token 与 API 地址。
- 在**另一个源**执行 bookmarklet 能把当前页写入本机书签；不带 token 的跨域写入被 401 拒绝。
- 跨域访问其它接口返回 403；同源请求不受影响。
- 扩展 manifest 合法可加载，popup 带 token 设置。
- `/bookmarks?url=&title=` 能预填并提示。
- 测试、冒烟、浏览器断言通过。

**不做**

- 扩展上架、图标设计、桌面壳（M9）、PWA 离线缓存、token 自动轮换。

## 2 做了什么

1. 新增 `app/core/tokens.py`：按 `API_TOKEN_PATH` 读写本地 token（首次自动生成，`hmac.compare_digest` 比较）。
2. `app/routers/tools.py`：`GET /api/tools/bookmarklet` 返回单行 `javascript:` 代码、token、API 基址。
3. `main.py` 增加跨域中间件：只放行 `/api/bookmarks*`，必须带 `X-CS-Token`；预检 `OPTIONS` 返回 204；其它 `/api/*` 跨域一律 403；同源直接放行。
4. 前端 `/tools` 页面：bookmarklet 拖拽入口（React 拦截 `javascript:` href，挂载后用 DOM 设置）、复制代码、扩展安装步骤、token 展示。
5. `apps/extension/`：MV3 最小扩展（popup 保存当前页 + 连接设置里填 API/token），README 说明加载方式。
6. PWA：`manifest.webmanifest` 带 `share_target`（GET → `/bookmarks`）；`index.html` 引用 manifest 与 theme-color；`BookmarkPage` 读取 `url/title` 预填并提示。
7. 冒烟增加「跨域 token 拦截 401」。

## 5 关键决策

| 决策 | 备选 | 理由 |
| --- | --- | --- |
| 跨域写入用 token 而非 Origin 白名单 | 列白名单 `chrome-extension://` | bookmarklet 在任意站点执行，Origin 无法枚举；扩展 ID 也随安装方式变化 |
| 只放行 `/api/bookmarks*` | 全 API 跨域 | 搜索/总结没有跨域需求，面越小越好 |
| 预检无条件 204 | 预检里验 token | 预检不能带自定义头，只能在真正请求上验 |
| bookmarklet 端点返回明文 token | 只显示掩码、让用户手抄 | 用户要把它填进扩展；本机单用户，同源可读已经足够 |
| PWA 用 GET share_target、不注册 SW | POST + Service Worker 拦截 | GET 免 SW；不做离线缓存，避免装完读到旧页面 |
| React 里用 ref 写 `javascript:` href | 直接 `href={code}` | React 19 会把 `javascript:` 替换成报错字符串 |

## 6 遗留与风险

- token 是静态共享密钥，没有过期；泄露需手动删 `data/api-token.txt` 并重填扩展。
- 跨域允许 `Access-Control-Allow-Origin: *`，任何网页都能探测服务是否存在（但写书签需 token）。
- 扩展未在真实浏览器加载验证；未提供图标，安装后是默认占位。
- PWA 无离线缓存；断网时安装的 App 只能看到错误页。
- 分享目标预填后仍需手动点「收藏」，没有做自动保存（担心误触写库）。
