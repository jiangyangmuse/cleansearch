## 5 关键决策

| 决策 | 备选 | 理由 |
| --- | --- | --- |
| Compose 数据写入命名卷 | 随容器写入本地层 | 重建 API 不应丢书签，且主机端 SQLite 路径保持原约定。 |
| 把受控冒烟与真实上游验收分开 | 用 fixture 的搜索结果代表真实可用性 | 搜索服务的可用性和路由需由实际部署的引擎证明。 |
| 按等价请求地址处理完整 URL 黑名单 | 按域名扩大拦截 | 阻断显示形式变化造成的绕过，同时保留同站其他路径和查询。 |
| PATCH 使用显式 null 清除分组 | 重复收藏来改分组 | 单独支持移回未分组，省略字段不影响已有分组。 |

## 6 遗留与风险

- M0/M1 真机验收仍缺：本机 SearXNG 无响应，Docker/Podman 不可用。暂未验证容器启动、重建后 SQLite 保留，以及真实引擎和真实搜索接千问。
- M3 已跑 HTML 往返回归和启动台浏览器操作，未在 Chrome / Edge / Firefox 的原生书签管理器逐一回灌。旧版容器若已有书签，升级前按 README 导出备份，再重建并导入。

## 7 交接

在部署机启动 Compose 后先运行 `python scripts/verify-searxng.py --engines g b`，把实际启用引擎、成功率和延迟追加到本报告；用测试书签复验 API 容器重建后的持久化。详见 [README](../../README.md) 和 [决策与接口](../../docs/决策与接口变更.md)。
