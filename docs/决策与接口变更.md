### 契约字段锁定（M0）

`SearchRequest`：`q`（必填，1–512 字，去空白后非空）、`page`（1–10）、`region`、`opts.{safe,exact,summarize,fixture}`。

`Result`：`id/url/display_url/title/snippet/engine[]/score/risk/reasons[]/favicon/published/read_minutes`。
M0 填 `id … favicon` 与 `published`，`risk` 恒 0、`read_minutes` 恒 null（M1 / M4 补）。

`meta`：`status/engines/unresponsive/provider/cached/ms/total/filtered.{dup,risk}/sid`。

### 已知限制

- `fixture` 样本只有一页，`page>1` 返回零结果（可预期，不是 bug）。
- 真实模式未做引擎熔断与结果缓存（M1 / M7）。
- 前端未做相关性与弱相关渲染，等 M1 打分管线落地。

## 2026-11-06 · M0～M3 联合复核

- Compose 继续只向宿主机回环发布端口。容器 API 支持 `/app` 目录布局；书签库固定为 `/data/cs.db`，由命名卷保留。Compose 通过 `COMPOSE_LLM_BASE_URL` 配置容器可访问的模型地址，缺省不继承宿主机 Ollama 的回环地址。
- 固定样本自检入口只在检索后端为 `fixture` 时显示。真实上游验收用 `scripts/verify-searxng.py`，与固定样本冒烟分开统计。
- 黑名单的完整 URL 规则统一协议和主机大小写、默认端口及片段后再匹配。路径（除尾斜杠）和查询串仍需一致，非默认端口仍区分。
- `meta.sid` 仍是不透明字符串，改用 128 位随机数，降低并存快照发生同 ID、导致总结串到其他查询的概率。AI 首段正文的总时限从发请求前起算，包含等待响应头；拿到正文后按流读取超时执行。
- `PATCH /api/bookmarks/{id}` 中，`group_id` 缺省表示保留分组，整数表示移到指定分组，`null` 表示移回未分组。启动台的书签卡可直接移组。重复收藏与导入语义保持原约定。
