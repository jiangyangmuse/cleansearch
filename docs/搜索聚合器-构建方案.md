# 干净搜索聚合器 · 构建方案

> 版本 v1.0 ｜ 2026-11-05 ｜ 状态：设计定稿，待开工
> 代号：CleanSearch（工作名，可改）
> 一句话：聚合多引擎检索 + 无广告无钓鱼的结果页 + 三档相关性分组 + 侧栏 AI 总结 + 书签启动台。

首版技术选型、开工顺序和验收标准见 [《搜索聚合器首版实施计划》](搜索聚合器-首版实施计划.md)。

## 0 摘要与决策记录

**可行性结论**：可行。功能上没有任何一项需要"从零写浏览器内核"。全部需求落在三个可独立交付的层次上：检索聚合层、自有 UI 层、LLM 总结层。

**最大分水岭**：点开搜索结果之后，页面归谁承载。

| 选项 | 形态 | 能否做页面级拦截 / 广告屏蔽 / 任意网页总结 |
|---|---|---|
| 新标签页打开原站 | PWA | 只有结果层过滤，页面内广告归原站 |
| 浏览器扩展 | PWA + Extension | 能：declarativeNetRequest 拦截、右键总结、一键加书签 |
| 自建容器 | Tauri / Electron | 能，且体验最接近"自己的浏览器" |

iframe 方案作废：`X-Frame-Options` 与 CSP `frame-ancestors` 会拒绝绝大多数站点的嵌入，代理渲染又会破坏登录态与交互。

**已确认的技术决策**

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 检索层用自建 SearXNG 做统一入口 | 一次拿多引擎结果、天然无广告、支持 bang、零 API 费用 |
| D2 | 商业 API 作为兜底而非主力 | 上游引擎会 CAPTCHA/限流，需要有付费回路保底 |
| D3 | 后端用 FastAPI（Python） | 抓正文、中文分词、向量化、PDF 解析生态更顺 |
| D4 | 存储用 SQLite + FTS5 | 个人/小团队规模零运维，随机读极快 |
| D5 | 三档分组用"公式打分 + LLM 复核"双层 | 纯阈值切分会把垃圾塞进弱相关栏 |
| D6 | 总结走流式 SSE + 强制引用编号 | 首字延迟可控，且幻觉引用可见可控 |
| D7 | 书签一键添加走"扩展 / bookmarklet / PWA share"三通道 | 网页 JS 写不进系统书签栏，这是物理边界 |

## 1 目标与非目标

### 1.1 目标

1. 搜索结果页零广告、零钓鱼入口，垃圾站不进主栏。
2. 两页结构：搜索页、书签启动台。
3. 搜索页在保留网页结果的同时，侧边输出 AI 总结，不遮挡结果。
4. 支持对任意网页做结构化总结。
5. 结果按"强相关 / 相关 / 弱相关"三板块分组。
6. 输入后缀即可指定搜索引擎与地区（`数分知识点 g` → Google）。
7. 书签支持一键添加、分组、快速启动、导入导出。

### 1.2 非目标（本期不做）

- 多用户账号体系与权限（单人使用，预留 schema）。
- 图片 / 视频 / 新闻 / 地图的垂直搜索（架构预留 `type` 参数）。
- 自建爬虫与索引（不做独立索引，只做聚合）。
- 广告拦截规则集的社区维护（直接引 EasyList）。

## 7 核心模块设计

### 7.1 查询解析器

规则优先级：`bang` > `后缀短码` > `默认`。

```ts
const ENGINES: Record<string, string> = {
  g: 'google',   b: 'bing',   d: 'duckduckgo', ddg: 'duckduckgo',
  br: 'brave',   yt: 'youtube', gh: 'github',  ar: 'arxiv',
  sc: 'scholar', w: 'wikipedia',
  zh: 'cn', cn: 'cn', jp: 'jp', us: 'us', en: 'en',
};

export function parseQuery(raw: string) {
  const q = raw.normalize('NFKC').trim();

  // 1) bang：无歧义优先
  const bang = q.match(/\s*!([a-z]{1,3})$/i);
  if (bang && ENGINES[bang[1].toLowerCase()])
    return { q: q.slice(0, bang.index).trim(),
             engine: ENGINES[bang[1].toLowerCase()], router: 'bang' };

  // 2) 后缀短码：前面必须有空白，且必须是纯 ASCII 字母
  const m = q.match(/\s+([a-z]{1,3})$/i);
  if (m && ENGINES[m[1].toLowerCase()])
    return { q: q.slice(0, m.index).trim(),
             engine: ENGINES[m[1].toLowerCase()], router: 'suffix' };

  return { q, engine: 'default', router: 'default' };
}
```

护栏：
1. 短码前必须是空白（含全角空格 `\u3000`），`C g` 这类单字母前置于数字/单字母时降级为普通查询。
2. 引号内不解析：`"sort g"` 保持原样。
3. `!g` 与 ` g` 双写法并存，bang 给习惯 DuckDuckGo 的用户，后缀给中文输入场景。

后缀映射表（可在 `config.py` 里扩展为 JSON 配置）：

| 后缀 | 引擎 / 地区 | 说明 |
|---|---|---|
| `g` | Google | 主用 |
| `b` / `d` | Bing / DuckDuckGo | 备用 |
| `br` | Brave | 独立索引 |
| `yt` `gh` `ar` `sc` `w` | YouTube / GitHub / arXiv / Scholar / Wikipedia | 垂类 |
| `zh` `cn` | 中文区（百度 + 360 + 搜狗） | 地区切 |
| `jp` `us` | 对应 locale 引擎集 | 地区切 |
| 无 | 默认多引擎聚合 | 主力路径 |

### 7.2 检索聚合

```
for engine in selected_engines:      # 并发，asyncio.gather
    if breaker_open(engine): skip
    fetch with timeout=2.0s
    on success -> record ok, reset fails
    on fail    -> fails += 1; fails >= 3 -> open 3600s
```

- 主路径：`SearXNG /search?q=...&format=json&engines=...`
- 回退链：SearXNG → Brave API → Serper，任一成功即停。
- 引擎子集由解析出的 `engine`/`region` 决定；默认取 3–5 个健康引擎，避免结果同质化。

### 7.3 去重与归一化

```python
def canonical(url: str) -> str:
    u = urlsplit(url.strip())
    q = [(k, v) for k, v in parse_qsl(u.query)
         if k.lower() not in TRACKING_PARAMS]        # utm_*, fbclid, gclid, spm
    path = u.path.rstrip('/') or '/'
    return urlunsplit((u.scheme.lower(), u.netloc.lower(), path,
                       urlencode(sorted(q)), ''))
```

二级去重：标题 simhash（64 位，汉明距离 ≤ 3）判同稿，保留权威度最高的那条并合并 `engine` 列表。

### 7.4 安全过滤

**三源黑名单（本地缓存 6h）**

| 源 | 用途 | 接入要点 |
|---|---|---|
| Google Safe Browsing Lookup v4 | 恶意/钓鱼/垃圾站 | 免费，默认配额够个人用；**仅限非商用**，商用换 Web Risk |
| URLhaus | 恶意软件分发 | **2025-06-30 起必须带 Auth-Key** |
| OpenPhish Community | 钓鱼 URL | 免费无 key，12 小时更新 |

**启发式风险分**

```python
risk = (0.45 * feed_hit          # 黑名单命中 0/1
      + 0.20 * age_penalty       # <90 天 = 1.0（无 RDAP 记录 0.8）, <1 年 = 0.5
      + 0.15 * tld_penalty       # .zip .top .xyz .tk .icu .cyou → 1.0
      + 0.10 * url_shape         # IP 直连 / 超长随机串 / >4 层子域 / user@host
      + 0.10 * homoglyph)        # punycode(xn--) / 形近字(0-O, rn-m, 1-l)
```

处置：`risk ≥ 0.6` 折叠隐藏；`0.35 ≤ risk < 0.6` 保留但跳转走 `/go` 中转确认页；`< 0.35` 放行。

**质量分（独立于风险分）**：标题堆叠关键词（关键词密度 > 25%）、正文 < 200 字、域名是已知聚合站、与查询语义漂移（出现"加微信/客服/限时优惠/下载APP"等营销词且查询无相关意图）→ 直接进弱相关或丢弃。

> 边界说明：黑名单是概率保证，时延从几分钟到几小时。域名年龄 + 跳转确认两层兜底是必需的，不能只依赖 feed。

### 7.5 打分与三档分组

| 特征 | 计算 | 权重 |
|---|---|---|
| 词法 | BM25(query, title×2 + snippet)，jieba 分词 | 0.30 |
| 语义 | cos(emb(q), emb(title+snippet)) | 0.30 |
| 引擎共识 | 出现在 n 个引擎 top10 → min(n,3)/3 | 0.15 |
| 权威度 | 域名白名单（.gov/.edu/官方文档/Wikipedia/GitHub/期刊） | 0.10 |
| 时效 | 查询含时间意图时，按 published 距今衰减 | 0.05 |
| 负向 | 风险分 ×−0.15、spam 特征、内容农场、标题党 | −0.20 ~ 0 |

```python
def group_results(results, n_strong=10, n_mid=10, n_weak=5):
    for r in results:
        r.score = (0.30 * norm_bm25(r)
                 + 0.30 * r.sem
                 + 0.15 * r.consensus
                 + 0.10 * r.authority
                 + 0.05 * r.freshness
                 - 0.15 * r.risk
                 - 0.10 * r.spam)
    s = minmax_scale([r.score for r in results])
    strong  = [r for r, x in zip(results, s) if x >= 0.62][:n_strong]
    mid     = [r for r, x in zip(results, s) if 0.35 <= x < 0.62][:n_mid]
    weak    = [r for r, x in zip(results, s) if x < 0.35][:n_weak]
    return strong, mid, weak
```

**双层机制（精确模式）**：公式先秒出三档 → 后端把 20 条 `{title, snippet, domain}` 打包成一次 LLM batch 判定（约 500 token）→ 前端显示"正在校准…" → 判定回来重排并给每条附一句"为什么"。成本可忽略，准确率明显更稳。

空组不渲染；弱相关默认折叠，展开后才加载 favicon。

### 7.6 总结管线（RAG-lite）

```
1. 取 top 8~12 条结果
2. 并发抓正文（6~8 并发，2.5s 超时，失败降级用 snippet）
3. 正文提取：trafilatura → 失败走 readability → 再失败走 r.jina.ai
4. 每篇截断 2000~3000 token，保留标题/URL/发布日期
5. 组装 prompt，强制引用编号
6. SSE 流式输出；同步维护 citations 数组
7. 落库：summaries(content_hash) / search_cache(qkey)
```

延迟预算：检索 0.8–2s → 抓正文 1.5–2.5s → 首 token 2.5–4s。
优化手段：`mode=fast` 先出结果、再升级；正文抓取按域名做优先级（权威域名先抓）；命中缓存直接复用。

### 7.7 网页总结管线

```
URL → 抓取（正常 UA、遵守 robots.txt）
    → JS 站点用 Playwright 兜底
    → 正文提取 → 按标题层级分块
    → ≤30k token 直接总结；超出走 map-reduce（块摘要 → 合并 → 冲突消解）
    → 固定结构输出
```

输出结构固定为五段：一句话结论 / 5 条要点 / 关键数据表 / 争议与不确定点 / 原文锚点。
失败场景（付费墙、反爬、纯图片）→ 明确标注"仅基于摘要生成，置信度低"。

```python
async def gather_results(q: str, engines: list[str], page: int) -> list[dict]:
    async with httpx.AsyncClient(timeout=2.0) as cli:
        tasks = [fetch_one(cli, q, e, page) for e in engines if not breaker.is_open(e)]
        done = await asyncio.gather(*tasks, return_exceptions=True)
    out = []
    for e, r in zip(engines, done):
        if isinstance(r, Exception):
            breaker.fail(e)
            continue
        breaker.ok(e)
        out.extend(r)
    return out
```

### A.3 标题 simhash

```python
def simhash(text: str, bits: int = 64) -> int:
    v = [0] * bits
    for w in jieba.cut(text):
        h = hash64(w)
        for i in range(bits):
            v[i] += 1 if (h >> i) & 1 else -1
    return sum(1 << i for i in range(bits) if v[i] > 0)
```
