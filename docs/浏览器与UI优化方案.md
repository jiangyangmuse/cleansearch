## 0 结论摘要

功能面已经比较完整：聚合搜索、三档分组、官方入口、分类视图、引擎后缀、AI 检索/总结/翻译/对话、书签启动台、单页总结、bookmarklet、MV3 扩展、PWA 清单都已存在。当前问题主要不在“再做一个功能”，而在三件事：

1. **浏览器语义不完整**：搜索、分类、翻页全部走 `replaceState`，地址栏不形成历史；后退直接离开应用；第 2 页刷新回第 1 页；结果页标题仍是 `CleanSearch`。
2. **窄屏信息架构倒置**：移动端把书签快捷栏和 4 个工具按钮放在结果之前；390×844 首屏看不到任何一条自然结果（第一条卡片 y=1017）。打开 AI 总结又把结果整体推下 421px。
3. **细节状态不可信**：引擎菜单点外部不关闭；“中国大陆可直连”标题下实际混入 16 个非大陆引擎；20 个引擎开关全部 `disabled`，但 12 个显示为开启且透明度为 1；旧页面 header 与正文错位 140px。

建议按 P0 → P1 → P2 三轮推进：P0 先修浏览器语义、移动端抽屉、触控尺寸和上述状态 bug（约 2–3 人日）；P1 再做首屏效率、结果可读性和统一 AppShell（约 4–6 人日）；P2 补 PWA/扩展/分享/搜索建议等浏览器生态能力（约 5–8 人日）。

## 3 设计原则

1. **结果优先**：首屏第一屏必须能看到“结果条数 + 至少一条结果”；工具、书签、统计都后置。
2. **浏览器原生语义**：每个可分享状态都进 URL；前进/后退/刷新/复制链接都能复现；标题跟随查询。
3. **一套 AppShell**：搜索、设置、书签、工具、单页总结共用品牌、导航、主题和移动端折叠规则。
4. **状态可辨**：hover / active / selected / disabled / loading / saved / error 必须有不同视觉，不能只靠颜色或文字。
5. **触控基线**：主要控件 ≥44×44；行内文字链接至少 24×24 或保证间距；辅助字号 ≥12px。
6. **渐进披露**：统计、sid、引擎列表、诊断命令默认收起；需要的人一键展开。
7. **搜索页断点**：宽度 >1180px 时三栏，≤1180px 时单列、横向分类导航与工具抽屉。书签页按 900px 切换。
